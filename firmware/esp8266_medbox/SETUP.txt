CareBee MedBox / ESP8266

เตรียมบอร์ด
1. เปิด esp8266_medbox.ino จากโฟลเดอร์ esp8266_medbox ใน Arduino IDE
2. เลือก NodeMCU 1.0 (ESP-12E Module) และ Flash Size ที่มีพื้นที่ FS
3. ติดตั้ง ESP8266 core 3.1.2 และ ArduinoJson 7, PubSubClient, RTClib,
   Adafruit SSD1306, Adafruit GFX, Adafruit BusIO และ HX711 Arduino Library
4. แก้ config.h ให้ตรงกับบอร์ดจริง โดยเฉพาะขา I2C, buzzer, LED, HX711
   และปุ่ม ขา D8 อ้างจากข้อความ log ในต้นฉบับ ขาอื่นเป็นตัวอย่าง
   เช็กขั้ว BUZZER_ACTIVE_LOW ด้วย ใช้ค่าจริงจาก config.h เดิมถ้ามี
5. ตั้ง Wi-Fi, broker, Device ID และ Device Key ของอุปกรณ์ทดสอบ
   ค่า broker เดิมเป็น public MQTT ที่ส่งแบบ plaintext ใช้เฉพาะข้อมูลทดสอบ
   ระบบใช้งานจริงควรใช้ broker ส่วนตัวที่ยืนยันตัวตนและเชื่อมต่อผ่าน TLS
6. เปิด CAREBEE_USE_BUTTONS หลังต่อปุ่มและตรวจขาแล้ว ตั้ง
   CAREBEE_ENABLE_SERIAL_TEST เป็น 0 เมื่อส่งมอบ
   การรับยาใช้การกดปุ่มหลังหยิบยา IR ในต้นฉบับใช้ปิดเสียง
   ส่วน HX711 วัดน้ำหนักรวม การตรวจว่าหยิบจากช่องไหนต้องใช้เซ็นเซอร์ที่เหมาะกับช่องนั้น

สัญญาข้อความ MQTT ตามสเก็ตช์เดิม
- บอร์ด subscribe medicine/schedule/<deviceId> และ publish medicine/sensor/<deviceId>
- หลังเชื่อมต่อและทุก 30 วินาที บอร์ดส่ง
  {"type":"schedule_request","deviceId":"<deviceId>"}
- ฝั่งเว็บหรือ backend ส่งหนึ่งข้อความต่อช่อง เช่น
  {"compartment":6,"time":"19:45","days":[0,1,2,3,4,5,6]}
  เวลาเป็น HH:mm แบบ 24 ชั่วโมง ตามเวลาไทย วันอาทิตย์ = 0 วันเสาร์ = 6
  ไม่ส่ง days หมายถึงทุกวัน ระบุ days เป็น [] หรือ time เป็น null เพื่อปิดช่อง
- บอร์ดเก็บตารางใน LittleFS แล้วส่ง schedule_ack เมื่อมีเวลาที่พร้อมใช้
  ในรุ่นนี้ ACK ต้องรอ DS3231 พร้อม เพราะเว็บปิดการเตือนจากเซิร์ฟเวอร์เมื่อได้
  ACK ครบ 6 ช่อง ถ้ามีแต่ NTP บอร์ดยังเตือนได้เมื่อมีเวลาที่ซิงก์แล้ว
  ตั้งโปรไฟล์เว็บเป็น Asia/Bangkok ให้ตรงกับเวลาท้องถิ่น UTC+7 บนบอร์ด
- รายงานการรับยาที่บอร์ดส่ง เช่น
  {"deviceId":"<deviceId>","device_key":"<testKey>","compartment":6,"weight":null,"isTake":true,"scheduledDate":"2026-11-29"}
- Backend ต้องบันทึกแบบ idempotent ตาม deviceId + compartment + scheduledDate
  เมื่อบันทึกสำเร็จแล้ว ให้ publish กลับไปที่ medicine/schedule/<deviceId>
  {"type":"intake_ack","compartment":6,"scheduledDate":"2026-11-29"}
  ส่ง ACK ซ้ำได้เมื่อได้รับรายงานซ้ำที่บันทึกไปแล้ว
  ตารางปัจจุบันรองรับหนึ่งมื้อต่อช่องต่อวัน
- หากเน็ตหลุด บอร์ดเตือนจากตารางที่เคยบันทึกไว้เมื่อเวลาพร้อม
  คิวรับยารอ ACK อยู่ใน LittleFS ได้ 12 รายการและไม่หายเมื่อรีสตาร์ต
  การแฟลชแบบล้าง Flash ทั้งหมดจะล้างตารางและคิว

ทดสอบวันรวมทีม
เปิดเว็บด้วยบัญชีเจ้าของกล่อง เลือก broker เดียวกับบอร์ดและเชื่อม MQTT ค้างไว้
แท็บเว็บทำหน้าที่ส่งตารางและรับรายงานเพื่อส่งเข้า backend เมื่อปิดแท็บ บอร์ดเตือน
จากตารางที่เก็บไว้ได้และส่งรายงานซ้ำจนกว่าจะเปิดเว็บกลับมาแล้วได้รับ ACK
1. เปิด Serial Monitor ที่ 115200, Newline พิมพ์ clock แล้วดู ready=yes
2. ตั้งช่อง 6 บนเว็บให้เตือนในอีก 1–2 นาที ดู [SCHEDULE] และ [SCHEDULE_ACK]
3. รอดู [REMIND] และฟัง buzzer จากนั้นหยิบยาแล้วกดปุ่มรับยา
   หากยังไม่ต่อปุ่ม พิมพ์ take 6 ตอนช่อง 6 กำลังเตือน
4. ดู [QUEUE] แล้วเช็กว่า backend บันทึกและบอร์ดแสดง [INTAKE_ACK]
   คำสั่ง sensor 6 ใช้ส่งข้อมูลทดสอบ isTake=false เท่านั้น
5. ทดสอบซ้ำโดยตัด Wi-Fi หลังรับตาราง ให้ RTC เดินต่อและรับยาตอนออฟไลน์
   รีสตาร์ตบอร์ดแล้วเปิด Wi-Fi ตรวจว่ากู้คิวและส่งรายการเดิมจนได้ ACK
   ตรวจว่าเว็บแสดงรายการเดียว และบอร์ดไม่เตือนมื้อเดิมที่รับยาแล้วอีก

สถานะการตรวจ
คอมไพล์ผ่านสำหรับ NodeMCU 1.0 และผ่านเทสต์จำลอง MQTT กับ LittleFS
ต้องตรวจซ้ำกับบอร์ด, broker และ backend ของทีม
