# PoC กล่องยา 6 ช่องผ่าน MQTT และ RTC

## เปิดใช้บน CareBee

1. ให้ Lovable ใช้ [SQL สำหรับกล่อง 6 ช่อง](sql/enable-six-channel-rtc.sql) ใน migration ใหม่ หรือรันทั้งไฟล์ใน SQL editor ของ CareBee remix ที่ถูกต้อง ต้องมี migration ผูกยากับกล่องและสคริปต์แก้ owner_id ก่อนแล้ว
2. สร้างหรือแก้ยา เลือกกล่องจริงและช่วงทานยา ช่อง 1–6 คือ เช้าก่อน เช้าหลัง เที่ยงก่อน เที่ยงหลัง เย็นก่อน เย็นหลัง ยาในช่องเดียวกันใช้เวลาเดียวกัน การแก้เวลาเปลี่ยนให้ยาทั้งหมดในช่องนั้น
3. ในกล่อง เปิด **การตั้งค่า ESP32 · MQTT** เลือก broker ให้ตรงกับบอร์ด และเปิด **เก็บเวลาเตือน 6 ช่องบน ESP32** ก่อนกดเชื่อมต่อ การเชื่อมต่อที่บันทึกก่อนฟีเจอร์นี้ให้ตัดแล้วเลือกโหมดใหม่
4. เปิด **รูปแบบข้อความ MQTT สำหรับ ESP32** เพื่อดู topic และ JSON ที่สร้างจากตารางจริงของกล่อง กดคัดลอกได้แต่ละช่อง time เป็น HH:mm แบบ 24 ชั่วโมง time เป็น null หมายถึงปิดช่องนั้น หากไม่ได้เตือนทุกวันจะเพิ่ม days โดย 0=อาทิตย์ ถึง 6=เสาร์

เว็บส่งทั้ง 6 ช่องเมื่อเชื่อมต่อ เมื่อเปลี่ยนตาราง และเมื่อบอร์ดขอตารางอีกครั้ง ตรวจค่าล่าสุดซ้ำทุก 5 วินาทีขณะเชื่อมต่อ เฟิร์มแวร์ตอบ schedule_ack หลังบันทึกลงหน่วยความจำ เมื่อรับครบและตรงกับค่าปัจจุบัน เว็บแสดงว่าซิงก์แล้ว และหยุดงานส่งเตือนจากเซิร์ฟเวอร์ของกล่องนั้น

## โค้ด ESP32 ตัวอย่าง

ใช้ [carebee_rtc.ino](../firmware/carebee_rtc/carebee_rtc.ino) เป็นตัวอย่างสำหรับ **DS3231** ชื่อรุ่น RTC ของชุดจริงยังต้องยืนยันก่อนใช้ไลบรารี

ติดตั้ง PubSubClient, ArduinoJson รุ่น 7 และ RTClib แล้วใส่ WiFi, DEVICE_ID, DEVICE_KEY และ broker ที่ตรงกับเว็บ ESP32 ใช้ TCP 1883 เว็บใช้ WSS ของ broker เดียวกัน เช่น EMQX 8084 /mqtt หรือ HiveMQ 8884 /mqtt

กำหนด SDA/SCL, BUZZER_PIN สำหรับ Active Buzzer และ BUTTON_PINS ตามวงจรจริง ค่า -1 คือยังไม่ได้ใช้ขานั้น โค้ดตั้งเวลาปัจจุบันผ่าน NTP สำหรับ Asia/Bangkok (UTC+7) เมื่อเน็ตพร้อม ส่วน RTC เดินเวลาเองหลังจากนั้น

เวลาที่รับจาก MQTT เก็บใน Preferences ของ ESP32 ส่วน RTC เก็บเวลาปัจจุบัน เมื่อถึงเวลาของช่อง บอร์ดสั่ง Buzzer เมื่อยืนยันจึงปิดเสียงและเข้าคิวส่ง isTake กลับ topic เซนเซอร์ รอ intake_ack จากเว็บก่อนนำข้อความออกจากคิว ข้อความซ้ำไม่เพิ่มประวัติหรือหักสต็อกซ้ำ

โค้ดรับปุ่มยืนยันแยกช่องและคำสั่ง Serial `take 1` ถึง `take 6` สำหรับรอบที่กำลังเตือน ใส่โค้ด HX711 ที่น้องคาลิเบรตแล้ว โดยเรียก

```cpp
reportReading(1, weightInGrams, false); // รายงานน้ำหนัก
reportReading(1, weightInGrams, true);  // หลังตรรกะบนบอร์ดยืนยันว่าหยิบยา
reportReading(1, NAN, true);           // กดยืนยันเมื่ออ่านน้ำหนักไม่ได้
```

ตัวอย่างไม่ได้กำหนดเกณฑ์น้ำหนักแทนการคาลิเบรตจริง ให้ทดสอบค่านิ่งและความไวของ Load Cell ก่อนใช้การเปลี่ยนน้ำหนักเป็นตัวตัดสิน isTake ปุ่มและ Serial ใช้สำหรับยืนยันได้แม้น้ำหนักอ่านไม่ได้

## ข้อความที่ใช้

เว็บส่งไป topic แจ้งเตือนของกล่อง

```json
{"compartment":1,"time":"07:30"}
```

บอร์ดส่งกลับ topic เซนเซอร์ของกล่อง โดย deviceId เป็น UUID ที่สร้างใน CareBee และ device_key เป็นคีย์ลับที่ได้ตอนลงทะเบียนกล่อง

```json
{
  "deviceId": "<UUID>",
  "device_key": "<DEVICE_KEY>",
  "compartment": 1,
  "weight": null,
  "isTake": true,
  "scheduledDate": "2026-11-22"
}
```

scheduledDate ใช้วันที่ท้องถิ่นที่เกิดเหตุการณ์ เพื่อให้ข้อความค้างส่งกลับวันเดิม isTake=true ยืนยันยาทุกรายการที่มีกำหนดในช่องและวันนั้นอย่างเป็น transaction เดียว isTake=false ไม่ย้อนการยืนยัน น้ำหนักที่เปลี่ยนอย่างเดียวบันทึกสถานะ ส่วนการยืนยันขึ้นอยู่กับ isTake

## ขอบเขต PoC และทดสอบ

เปิดเว็บล็อกอินและต่อ MQTT ค้างไว้ระหว่างทดสอบ เพื่อให้เว็บรับข้อความแล้วบันทึกเข้าฐานข้อมูล เมื่อปิดเว็บ บอร์ดที่ซิงก์ตารางแล้วเตือนจาก RTC ได้เอง และเก็บการยืนยันรอส่ง เว็บจะบันทึกเมื่อเปิดกลับมาเชื่อม MQTT อีกครั้ง

1. ตั้งช่องหนึ่งให้อีก 2–3 นาที ตรวจข้อความขาออกและ Serial ว่าบอร์ดเก็บเวลานั้นแล้ว
2. รอข้อความซิงก์ครบ 6 ช่อง ตรวจว่า RTC ถึงเวลาแล้วเกิดเสียงเตือน
3. กดปุ่มของช่องนั้น หรือพิมพ์ take 1 ใน Serial ตรวจว่าเสียงหยุดและ Dashboard/ประวัติเปลี่ยนเป็นทานแล้ว
4. ปล่อยส่งข้อความเดิมซ้ำ ตรวจว่าสต็อกลดเพียงหนึ่งครั้งต่อรอบ
5. เปลี่ยนเวลาและปิดเตือน ตรวจว่า JSON และค่าที่บอร์ดเก็บเปลี่ยนด้วย
6. ปิดเว็บหนึ่งรอบแล้วกดยืนยันบนบอร์ด เปิดเว็บเชื่อมใหม่ ตรวจว่าข้อความค้างถูกบันทึกในวันที่เดิม

โค้ดเป็นตัวอย่าง PoC ต้องทดสอบคอมไพล์และพินกับบอร์ดจริง รวมถึงชนิด Buzzer และชื่อรุ่น RTC ของชุดน้อง

ตัวอย่างการอ่านและตั้ง RTC อ้างอิง [RTClib สำหรับ DS3231](https://github.com/adafruit/RTClib/blob/master/examples/ds3231/ds3231.ino) ส่วนการเชื่อม MQTT ใช้ [PubSubClient](https://github.com/knolleary/pubsubclient)

เมื่อทุกกล่องใช้ RTC แล้ว ผู้ดูแลสามารถปิด job `carebee-mqtt-reminders` ใน Lovable Jobs ได้ ส่วน PoC นี้ใช้เว็บที่เปิดเชื่อม MQTT รับสถานะ

## พิสูจน์ผ่าน MQTTX Desktop

ใช้กล่องทดสอบและยาทดลอง เพื่อให้ประวัติและการหักจำนวนยาจากการทดสอบตรวจสอบได้ชัดเจน เตรียมคีย์ของกล่องที่ได้รับตอนลงทะเบียน

### 1. เชื่อมทั้งสองฝั่ง

- เว็บเลือก EMQX Public และเปิดโหมดเก็บเวลา 6 ช่อง แล้วกดเชื่อมต่อ
- MQTTX ใช้ Host `broker.emqx.io`, Protocol `mqtt://`, Port `1883` และ Client ID ที่ต่างจาก ESP32 จริง
- คัดลอก topic จาก **รูปแบบข้อความ MQTT สำหรับ ESP32** ของกล่องที่ทดสอบ
- ใน MQTTX subscribe topic **เว็บ → ESP32** ก่อนเริ่มส่งข้อความ ตั้ง QoS 1 และปิด Retain ทุกครั้งที่ Publish

หากเลือก HiveMQ ให้ทั้งเว็บและ MQTTX ใช้ `broker.hivemq.com` โดย MQTTX ยังคงใช้ TCP 1883

### 2. พิสูจน์เว็บส่งตาราง

สร้างยาทดลอง ผูกกับกล่องและเลือกช่อง 1 ตั้งเวลาล่วงหน้า 2–3 นาที บันทึก ควรเห็น JSON บน topic แจ้งเตือน เช่น

```json
{"compartment":1,"time":"14:35"}
```

เวลาต้องตรงกับที่บันทึกจริง ช่องที่ไม่มีรอบเตือนจะส่ง time เป็น null และ days เป็น [] ระบบส่งครบ 6 ช่องเพื่อให้บอร์ดล้างเวลาเก่าที่ถูกยกเลิกได้ด้วย หากจำกัดวันจะมี days ในข้อความ

หาก MQTTX subscribe หลังจากเว็บส่งไปแล้ว ให้ publish ข้อความขอตารางไป topic **ESP32 → เว็บ**

```json
{"type":"schedule_request","deviceId":"<UUID กล่องทดสอบ>"}
```

ควรได้รับค่าปัจจุบันทั้ง 6 ช่องอีกครั้ง ลองแก้เวลาแล้วบันทึก ตรวจว่า MQTTX ได้เวลาใหม่

### 3. จำลองบอร์ดตอบรับตาราง

สำหรับแต่ละข้อความตั้งเวลาที่ได้รับ ให้ส่งกลับไป topic **ESP32 → เว็บ** โดยเพิ่ม type, deviceId และ device_key แล้วคง compartment, time และ days ตามข้อความที่ได้รับ

```json
{
  "type": "schedule_ack",
  "deviceId": "<UUID กล่องทดสอบ>",
  "device_key": "<คีย์ของกล่องทดสอบ>",
  "compartment": 1,
  "time": "14:35"
}
```

ส่งตอบรับให้ครบช่อง 1–6 ช่องว่างต้องส่ง time:null และ days:[] ด้วย เมื่อครบและตรงกับเวลาปัจจุบัน ในเว็บต้องแสดง **บอร์ดตอบรับว่าเก็บตาราง RTC แล้ว** ถ้าตอบเวลาเก่า จะยังไม่ยืนยันว่าซิงก์แล้ว

### 4. จำลองค่าน้ำหนักและการกดยืนยัน

ดูจำนวนยาคงเหลือก่อนทดสอบ แล้ว Publish ไป topic **ESP32 → เว็บ**

```json
{
  "deviceId": "<UUID กล่องทดสอบ>",
  "device_key": "<คีย์ของกล่องทดสอบ>",
  "compartment": 1,
  "weight": 12.4,
  "isTake": false
}
```

เว็บควรแสดงน้ำหนักของช่อง 1 และยังไม่ยืนยันการทาน จากนั้นส่งข้อความนี้โดยใส่วันที่รอบทดสอบตามเขตเวลาของบัญชี

```json
{
  "deviceId": "<UUID กล่องทดสอบ>",
  "device_key": "<คีย์ของกล่องทดสอบ>",
  "compartment": 1,
  "weight": null,
  "isTake": true,
  "scheduledDate": "2026-11-22"
}
```

ผลที่ต้องเห็น

- ขาเข้าเว็บแสดงว่าประมวลผลแล้ว
- ยาที่มีกำหนดในช่อง 1 วันนั้นเปลี่ยนเป็นทานแล้ว และจำนวนยาลดตามจำนวนต่อครั้งของยาแต่ละชนิด
- MQTTX ได้ข้อความตอบรับบน topic **เว็บ → ESP32**

```json
{"type":"intake_ack","compartment":1,"scheduledDate":"2026-11-22"}
```

วันที่ในตัวอย่างต้องเปลี่ยนให้ตรงกับวันที่กำลังทดสอบจริง

### 5. พิสูจน์การส่งซ้ำ

ส่ง isTake:true ข้อความเดิมอีกสองครั้ง ต้องได้ intake_ack อีก แต่จำนวนยาต้องไม่ลดเพิ่ม จากนั้นส่ง isTake:false ตรวจว่าประวัติที่ทานแล้วไม่ย้อนกลับเป็นรอทาน

หากมีสองชนิดยาในช่องเดียวกัน ให้สร้างทั้งสองรายการแล้วทดสอบการยืนยันครั้งเดียว ต้องขึ้นทานแล้วทั้งสองชนิดและลดจำนวนของแต่ละชนิดเพียงครั้งเดียว

### 6. พิสูจน์การยกเลิกเวลา

ปิดเตือนหรือลบยาทุกรายการออกจากช่องนั้น แล้วตรวจข้อความ time:null ของช่องนั้นใน MQTTX หากยังมียาอื่นที่เปิดเตือนในช่องเดียวกัน เวลาของช่องจะยังทำงาน

MQTTX ใช้พิสูจน์การส่งตาราง การบันทึกสถานะ และการกันข้อความซ้ำ ส่วนเวลา RTC เสียง Buzzer และปุ่มจริงให้ทดสอบกับบอร์ดต่อโดยใช้ขั้นตอนเดียวกัน
